# Deterministic generation foundations

Generation settings use seed `20261022`, fixed as-of date `2026-10-31`, fixed generation date `2026-10-31`, and three installments per loan in `settings.py`. Generation logic must derive dates from these constants; it must not consult the wall clock.

`rng.py` owns the singleton seeded `RNG` stream registry. It creates one NumPy `Generator` from a child `SeedSequence` for each named stream in `ENTITY_STREAMS`; `rng_for(entity)` returns the same child instance each time. Drawing from one entity's stream does not advance another entity's stream. Keep the stream-name order stable when extending the list so existing streams remain reproducible.

`ids.py` exposes deterministic `make_id(prefix, n, width)` plus `loan_id`, `installment_id`, `case_id`, `contact_id`, and `payment_id` helpers. IDs are returned as immutable strings; the same arguments always produce the same ID. `IdFactory` additionally issues sequential IDs, with installment and contact-attempt counters scoped to validated parent IDs.

Represent monetary values as integer cents (`MoneyCents`), including persisted amount columns. The canonical data dictionary uses `BIGINT` and integer-cent units for money. At input boundaries, use `decimal_to_cents` with `Decimal` or a decimal string; binary floats are rejected. Conversion rounds half-up to the nearest cent.

`ContactPreference` is effective-dated via `effective_from` and `effective_to`; contact history should be represented with new rows, not destructive updates. `schema/schema.sql` is hand-maintained and is not generated by `tools/generate_schema.py`.

These are generation primitives; dataset creation, exports, and complete reproducibility manifests remain planned. See `TRACEABILITY.md` for current implementation status.
